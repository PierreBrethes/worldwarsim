# Handoff — 12/09/2026 — timeouts Convex en prod

Session Cowork + Claude Code (Mac et VPS). Source de vérité : le repo (ADR 0022 révisée, ADR 0023 nouvelle).

## Symptôme de départ
`accounts:me` dépassait la seconde Convex (« Function execution timed out ») ; le plateau sautait avec « veuillez réessayer ».

## Ce qui a été trouvé, dans l'ordre
1. `accounts:me` lisait tous les `players` de toutes les saisons du compte, en boucle séquentielle, et le gardien racine `SignedIn` s'y abonnait — toute erreur démontait le plateau.
2. Le backend Convex est **auto-hébergé sur le VPS** (compose.prod.yml, Traefik), pas Convex cloud. La machine n'est pas le goulot (2 cœurs, 8 Go, charge ~0,3).
3. Vraie cause, dans les logs backend : `Restarting Isolate memory_carry_over` des dizaines de fois par jour, puis `user_timeout` en grappes. Le bundle serveur importait `regions.json` (2,5 Mo) et `world.json` (1,3 Mo) en littéraux : 45,6 Mio de tas à l'import de n'importe quelle fonction (61 sur 64, via `seasons.ts`). Chaque recyclage forçait un démarrage à froid sur la fonction suivante — d'où ~100 ms sur une query d'un document et les timeouts.
4. Effet de bord découvert en route : `goalCellsOfRegions` perdait 646 régions par collision de buts (une cellule = un but) — un retour de pillage vers ces régions n'avait pas de destination.
5. Victime collatérale : `press:publish` a dépassé 1 s le 12/09 à 23:55 (isolat froid, avant le raster). La mutation annulée emportait sa replanification — **la chaîne de presse s'arrêtait en silence sur un seul échec**.
6. Régression introduite puis corrigée le soir même : `useAccount` passait un objet neuf à `useQueries` à chaque rendu → React #301 sur toutes les pages (`useQueries` ne mémoïse pas, contrairement à `useQuery`). Corrigé par `useMemo` sur `[token]` + test de rendu (`src/routes/__root.test.tsx`, jsdom).

## Ce qui a été livré (tout en prod au 13/09 ~01:00, sauf le dernier point à pousser)
- `accounts.me` → `{ nickname }` seul ; `accounts.seats` pour l'accueil ; `seasons.playerCount` / `winnerNation` dénormalisés (migration `dev:backfillSeasonPreview` exécutée) ; `useAccount` tolère une erreur par-dessus une valeur connue, lève sinon.
- Raster « région + pays par cellule » à la maille de `grid.json` (`public/region-grid.json`, 414 Ko ; `projection.json` remplace `world.json` côté serveur) — 35,9 → 3,1 Mio à l'import. Garde-fous dans `scripts/mesure-isolat.mjs` ajouté au `verifier` (budget 10 Mio/module, espion d'import, égalité cuisson/calcul). ADR 0023.
- Canal d'ancrage pour les 971 régions sans cellule, `cellsOfRegion` totale, `goalCellsOfRegions` multi-buts (646 → 0 régions sans but).
- Correctif `useAccount` + test de rendu.
- **À pousser** : chaîne de presse séparée de l'édition (`publish` planifie le maillon suivant puis `runAfter(0, writeEditionJob)`) ; `dev:relaunchPress` (sans argument, idempotent, lit `_scheduled_functions`) documentée dans `deploiement/README.md`. **À lancer après CI** : `npx convex run dev:relaunchPress` avec les variables self-hosted — la chaîne de la saison en cours est morte depuis le 12/09 23:55.

## Décisions prises
- Le gardien racine est découplé de la liste des sièges (révision ADR 0022).
- La géographie serveur est un raster ; le franchissement est exact à la cellule, et la cellule est le modèle.
- Le relevé de couloir (`surveys.ts`, `coveredRegions`) **reste métrique** — ne pas le convertir au raster (règle de jeu, ADR 0020 §5).
- Régions plus petites qu'une cellule : ancrage sur la cellule de leur point intérieur (`region-index.json`), jamais une maille plus fine.
- Chaîne de presse et édition sont deux mutations ; `publishFinalEdition` reste dans la transaction de `concludeSeason`. Pas de surveillance au-dessus de la chaîne (ce serait un second planificateur).
